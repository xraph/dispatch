---
title: Memory Store
description: In-memory store for development, testing, and prototyping.
---

The memory store keeps all data in Go maps behind a mutex. It needs no configuration, which makes it the usual store for unit tests.

## When to use

- Unit tests: fast, deterministic, no external dependencies.
- Local development: get started without setting up a database.
- Prototyping: validate business logic before you pick a persistence layer.

Data is lost when the process exits.

## Usage

```go
import (
    "github.com/xraph/dispatch"
    "github.com/xraph/dispatch/store/memory"
)

s := memory.New()

d, err := dispatch.New(dispatch.WithStore(s))
```

The memory store implements `durable.Store`, so the durable workflow runtime works on it too.

## Internals

| Aspect | Detail |
|--------|--------|
| Concurrency | A mutex around the maps |
| Indexing | Map keys by ID string; linear scan for list/filter |
| Migrate | No-op |
| Ping | No-op (always succeeds) |
| Close | No-op |

## Limitations

- No persistence: all data is lost on restart.
- List operations are O(n) scans.
- Single process only.
- No multi-operation transactions.
