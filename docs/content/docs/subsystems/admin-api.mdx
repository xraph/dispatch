title: Admin API
description: HTTP admin API for managing Dispatch jobs, workflows, crons, and the DLQ.
---

The `api` package provides a REST API for managing Dispatch jobs, workflow runs, crons and the DLQ. Its routes are Forge routes grouped under `/v1`, and every one of them goes through an authentication and authorization guard.

## Setup

With the [Forge extension](/docs/guides/forge-extension) you don't call anything: it mounts the routes under its base path (`/dispatch` by default), so jobs live at `/dispatch/v1/jobs`. The guard authenticates through the Forge auth extension and authorizes with Warden. `WithRemoteSecurity(authenticator, boundary)` swaps in your own, and `WithDisableRoutes()` mounts nothing.

Outside the extension, build the handler yourself and give it security:

```go
import (
    "net/http"

    "github.com/xraph/dispatch/api"
)

a := api.New(eng, nil, api.WithSecurity(authenticator, boundary))
log.Fatal(http.ListenAndServe(":8080", a.Handler()))
```

`api.New(eng, router, opts...)` takes a `forge.Router`. Pass `nil` and `Handler()` creates one. To mount into a router you already have, call `a.RegisterRoutes(router)`. Without `api.WithSecurity`, every route answers 401.

## Routes

Paths below are relative to the mount point, so with the extension's defaults `/v1/jobs` is `/dispatch/v1/jobs`.

### Jobs

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/jobs` | List jobs |
| `GET` | `/v1/jobs/:jobId` | Get job by ID |
| `POST` | `/v1/jobs/:jobId/cancel` | Cancel a pending, retrying or running job |
| `POST` | `/v1/jobs/:jobId/retry` | Retry a failed job |
| `GET` | `/v1/jobs/counts` | Job counts by state |

### Workflows

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/workflows` | List workflow definitions |
| `GET` | `/v1/workflows/runs` | List workflow runs |
| `GET` | `/v1/workflows/runs/:runId` | Get a workflow run |
| `GET` | `/v1/workflows/runs/:runId/replay?step=` | Plan a replay from a step |
| `POST` | `/v1/workflows/runs/:runId/replay` | Replay a run from a step |

### Crons

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/crons` | List cron entries |
| `GET` | `/v1/crons/:cronId` | Get cron entry |
| `POST` | `/v1/crons/:cronId/enable` | Enable a cron entry |
| `POST` | `/v1/crons/:cronId/disable` | Disable a cron entry |
| `DELETE` | `/v1/crons/:cronId` | Delete a cron entry |
| `POST` | `/v1/crons/:cronId/trigger` | Enqueue the entry's job now |

### DLQ

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/dlq` | List DLQ entries |
| `GET` | `/v1/dlq/:entryId` | Get a DLQ entry |
| `POST` | `/v1/dlq/:entryId/replay` | Replay a single entry |
| `DELETE` | `/v1/dlq/:entryId` | Delete a single entry |
| `POST` | `/v1/dlq/replay-all` | Replay every unreplayed entry |
| `POST` | `/v1/dlq/purge` | Purge entries older than a cutoff |
| `GET` | `/v1/dlq/count` | DLQ entry count |

### Stats

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/stats` | System-wide statistics |

## Error responses

Errors come back as JSON with an `error` message. The guard answers 401 when there's no authenticated principal, 403 when Warden denies the request and 503 when the authorizer can't be reached.
