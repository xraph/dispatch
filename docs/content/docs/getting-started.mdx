## Prerequisites

- Go 1.26 or later
- A Go module (`go mod init`)

## Install

```bash
go get github.com/xraph/dispatch@latest
```

## Step 1: Create a Dispatcher

Every Dispatcher needs a store. For development and tests, use the in-memory store:

```go
package main

import (
    "context"
    "log"

    "github.com/xraph/dispatch"
    "github.com/xraph/dispatch/store/memory"
)

func main() {
    ctx := context.Background()

    d, err := dispatch.New(
        dispatch.WithStore(memory.New()),
        dispatch.WithConcurrency(4),
    )
    if err != nil {
        log.Fatal(err)
    }

    _ = ctx
    _ = d
}
```

If you leave out `WithStore`, `engine.Build` (the next step) returns `dispatch.ErrNoStore`.

## Step 2: Define a job

A job definition is a name and a typed Go function. Dispatch marshals the payload to JSON when you enqueue it and unmarshals it before your handler runs:

```go
import (
    "github.com/xraph/dispatch/job"
)

type EmailInput struct {
    To      string `json:"to"`
    Subject string `json:"subject"`
    Body    string `json:"body"`
}

var SendEmail = job.NewDefinition("send_email",
    func(ctx context.Context, input EmailInput) error {
        log.Printf("sending email to %s: %s", input.To, input.Subject)
        return nil
    },
)
```

## Step 3: Build the engine and register jobs

The `engine` package wires the subsystems together. `engine.Build` returns an error, so check it. Then register your definitions:

```go
import "github.com/xraph/dispatch/engine"

eng, err := engine.Build(d)
if err != nil {
    log.Fatal(err)
}
engine.Register(eng, SendEmail)
```

## Step 4: Start the dispatcher

```go
if err := d.Start(ctx); err != nil {
    log.Fatal(err)
}
defer d.Stop(ctx)
```

The workers start polling for pending jobs.

## Step 5: Enqueue a job

You enqueue by job name, not by definition:

```go
j, err := engine.Enqueue(ctx, eng, "send_email", EmailInput{
    To:      "user@example.com",
    Subject: "Welcome to Acme",
    Body:    "Thanks for signing up!",
})
if err != nil {
    log.Fatal(err)
}
log.Println("enqueued", j.ID)
```

`Enqueue` marshals the payload to JSON and stores the job in the `pending` state. A worker picks it up on its next poll. If the name isn't registered, the job still goes into the store, but no worker can run it.

A job gets 3 retries, the `default` queue and a 5 minute timeout unless you pass options to `Enqueue`:

```go
_, err = engine.Enqueue(ctx, eng, "send_email", input,
    job.WithQueue("critical"),
    job.WithMaxRetries(5),
    job.WithTimeout(time.Minute),
)
```

Pass queue, priority, retries and timeout at enqueue time. `job.NewDefinition` accepts the same options, but `Enqueue` doesn't read them from the definition today (only lease TTL, resources and artifact inputs carry over), so on a definition they have no effect.

## Step 6: The admin API (optional)

The REST admin API in the `api` package is a set of Forge routes, and every route refuses a request unless you configure an authenticator and an authorization boundary. The easy way to get it is the [Forge extension](/docs/guides/forge-extension), which mounts it under `/dispatch/v1` with Forge auth and Warden. Outside Forge you can build the handler yourself:

```go
import (
    "net/http"

    "github.com/xraph/dispatch/api"
)

h := api.New(eng, nil, api.WithSecurity(authenticator, boundary)).Handler()
log.Fatal(http.ListenAndServe(":8080", h))
```

`authenticator` is a `security.Authenticator` and `boundary` a `security.Boundary` from `github.com/xraph/dispatch/security`. Without `WithSecurity`, every route answers 401.
