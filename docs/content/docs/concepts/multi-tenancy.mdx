---
title: Multi-Tenancy
description: How Dispatch scopes jobs and workflows to app and organization contexts.
---

Multi-tenancy support is built into Dispatch via the `scope` package and the `ScopeAppID` / `ScopeOrgID` fields on every entity. It reads the scope from Forge, and without Forge the fields stay empty.

## Scope fields on entities

Every major entity carries scope fields:

| Entity | Fields |
|--------|--------|
| `job.Job` | `ScopeAppID`, `ScopeOrgID` |
| `workflow.Run` | `ScopeAppID`, `ScopeOrgID` |
| `cron.Entry` | `ScopeAppID`, `ScopeOrgID` |
| `dlq.Entry` | `ScopeAppID`, `ScopeOrgID` |

These fields are populated automatically from the context at enqueue time via `scope.Capture(ctx)`.

## The scope middleware

`middleware.Scope()` reads the scope fields from the job and restores them into the handler's `context.Context`. `engine.Build` puts it in the default middleware stack, so you don't add it yourself.

Inside a job handler, retrieve the scope:

```go
import "github.com/xraph/dispatch/scope"

func(ctx context.Context, input MyInput) error {
    appID, orgID := scope.Capture(ctx)
    // use appID / orgID to scope database queries
    return nil
}
```

## The scope package

`scope.Capture` returns empty strings when the context carries no scope:

```go
import "github.com/xraph/dispatch/scope"

appID, orgID := scope.Capture(ctx)        // "" when no scope is set
ctx = scope.Restore(ctx, appID, orgID)    // inject into context
```

The scope travels in the context through Forge's `forge.WithScope` and `forge.ScopeFrom`, so inside a Forge request handler the IDs are picked up automatically. `scope.Restore` sets them on any context.

## Per-queue tenant routing

Combine scope with per-queue configuration to isolate tenant traffic:

```go
eng, err := engine.Build(d,
    engine.WithQueueConfig(
        queue.Config{Name: "tenant-acme", MaxConcurrency: 5},
        queue.Config{Name: "tenant-beta", MaxConcurrency: 2},
    ),
)

// Enqueue to a tenant-specific queue:
engine.Enqueue(ctx, eng, "send_email", input, job.WithQueue("tenant-acme"))
```

Workers only poll the queues you list in `dispatch.WithQueues`, so add the tenant queues there too.
